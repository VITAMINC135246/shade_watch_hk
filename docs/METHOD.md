# Method — 1 km model and windowed execution

This is an independent reconstruction of Wu et al., *Shade Watch*, Sustainable Cities and Society 118 (2025), 106011. The supplied paper and earlier methodological record remain available in `references/` and [METHOD_legacy.md](METHOD_legacy.md). No alternative shadow engine or downloaded data are used.

## Preserved scientific interpretation

Solar geometry remains the existing NOAA approximation and refraction implementation in `src/solar.py`. Times are aware Asia/Hong_Kong instants; daylight samples remain clock-aligned at 10 minutes between calculated sunrise/sunset. Solar parameters use the geometric centre of the actual output for the entire output and are independent of chunk layout. This follows the 29 September user clarification: the saved location selects the default native tile, while its complete bounds and geometric centre define the output. In custom mode, the explicit custom centre (or saved centre when no override is given) defines the rectangle. Older 28 September results used the saved location as solar reference and remain unchanged. This spatially uniform solar model has not been evaluated over a whole-Hong-Kong region.

Azimuth is clockwise from north toward the Sun. The nearest 5° bin is used, including directions outside the paper's annual 40°–320° range when needed. Pixel-centred rays sample every 0.25 m from native DSM values; this integration interval is not a higher DSM resolution. Horizon elevation is `atan(max(0, (z-z0)/sample_distance))`. A target is shaded when the known horizon strictly exceeds apparent solar elevation. Shade is evaluated on the DSM surface, including canopy tops, not beneath trees or overhangs. Weather and thermal comfort remain outside scope.

The supplied metadata identifies EPSG:2326, HKPD, and LiDAR acquisition from 20 December 2019 to 2 February 2020. This predates the simulated 2026 scene. Source ownership attribution is retained in rasters and presentations. No observational accuracy is inferred from numerical agreement.

## Adopted distance rule and sampling

Production, the new single-region reference, validation comparisons and metadata use **1,000 m search and 1,000 m buffer**. The distance rule replaces the historical 1,500 m search/1,000 m support inconsistency. Historical results and method notes are retained as historical records only.

Nominal ray samples are at 0.25, 0.50, …, 1000.00 m inclusive. Nearest-cell sampling uses ties-to-even on **global pixel addresses**, defined relative to the one whole-output grid, including negative indices in the halo. Offsets are precomputed using global row/column parity; this avoids chunk-dependent floating-point addition and handles odd offsets. Near-zero cardinal-direction sine/cosine components are set to zero below 1e-14. A sampled cell is eligible only when its cell-centre horizontal distance from the target is also ≤1,000 m (1e-9 m² comparison allowance). Thus rounding cannot bring an obstruction physically beyond the model radius into the result. Out-of-radius cells are outside the adopted domain, not missing support. The slope denominator remains the nominal ray sample distance, preserving the existing profile integration convention.

The independent coarse QA ray uses 0.5 m sampling and the same 1 km cell-centre limit; it is a diagnostic, not the equality reference for the 0.25 m production operator. The historical rotated diagnostic is now distance-bounded too; it is not executed in production. The new equality reference processes the entire requested region as one core using the same defined input, target grid and 1 km operator.

## Source files, grid, and ownership

`src/spatial.py` reads GeoTIFF metadata and streams SHA-256 hashes. The production inventory also fingerprints associated external masks and auxiliary files reported by Rasterio, so changes to those dependencies invalidate cached horizons. Compatible source tiles share a north-up, square, metric projected grid, CRS and resolution; source dimensions need not be equal. Overlapping interiors and incompatible grids are rejected explicitly. The source inventory is lightweight and may grow with source count. Intersection tests currently scan that inventory, and compatibility/seam adjacency checks are pairwise; very large inventories may require a spatial tree for better runtime.

Native mode selects the containing source tile using west/north-inclusive and east/south-exclusive bounds, copies its bounds, shape, transform and CRS, and adopts the resulting geometric centre as its effective centre. The current selected tile is 750 × 600 m at 0.5 m. Custom mode preserves an exactly centred rectangle, with dimensions constrained to integer native pixels. Source values are nearest-neighbour mapped to its possibly fractionally shifted grid; ties exactly on a source cell edge select east/south. No elevation interpolation or invented filling occurs.

Native mosaic mode joins explicitly named source tiles into one aligned, complete rectangle and preserves their exact source boundaries as work units. Mixed tile dimensions, holes and duplicate selections are rejected. All tasks use the union’s geometric centre for shared solar parameters and the union’s statistics for one uncertainty threshold.

The output grid is fixed before row-major core enumeration. The user-selected default now derives a rectangular core width and height from the source tile containing the study centre: 1500 × 1200 pixels for the current DSM, so one native output tile is one spatial task. The task reads its buffered DSM once, then calculates the required azimuths and stores their caches; “one task” does not mean one shade label for the tile. For larger custom grids, these tile-sized cores start at the whole output grid origin, preserving exact-centre placement, and boundary cores may be partial. The optional fixed mode remains available for memory tuning. Each core owns one disjoint output window, including partial edge windows. Every core reads a halo of `ceil(1000/resolution)` cells per side. At the current 0.5 m this is exactly 2,000 cells; for non-dividing resolutions the outermost storage cell may extend past 1 km but the same radial calculation cutoff applies. Only intersecting source files are opened, one at a time, and source reads are at most 512 × 512 cells. Real neighboring elevations support edge and diagonal rays. Horizon files and final outputs contain only cores. No averaging or seam concealment is performed.

## Missing coverage and shared uncertainty threshold

A NaN elevation represents missing DSM, including source NoData and absent source tiles. Target NoData is quality 1. Known blockers still prove shade through a gap. A candidate sunlit pixel with any missing eligible ray sample is quality 2 and scientific NoData, not white. Nonpositive apparent solar elevation is quality 4.

The preserved low-sun sensitivity threshold is `atan(max(0, max_buffered_height - min_output_height)/1000)`. It is computed once from bounded-window scans of the **whole output and whole buffered extent**, then shared across all chunks. Candidate sunlight with complete support but elevation at or below this threshold is quality 3. This threshold describes a hypothetical obstruction based on observed extremes; it does not establish a bound on unseen terrain. The 1 km model boundary does not demonstrate that more distant terrain is harmless.

## Bounded execution, persistence, and presentation

`src/pipeline.py` separates scientific calculation from task scheduling. Each worker owns one core's buffered DSM and computes one azimuth at a time. Pending futures never exceed worker count; there is no eager list of all chunk arrays. GDAL cache is limited to 32 MiB per worker. Source statistics use 512² windows. Seam statistics use only adjacent boundary windows and fixed-size histogram bins (0.01 m; overflow ≥1000 m), reporting exact count/mean/max and bounded approximate quantiles.

Core/direction caches publish atomically with status, parameters through their definition key, grid, algorithm, source identities and checksum. A restart verifies checksum, raster structure, grid, horizon range, support values and blocker distances. Corrupt/incomplete tasks are rerun. Final label/quality files write core windows into temporary GeoTIFFs before rename; final status contains both hashes so interruption between publication steps is recoverable. A single-output lock and shared-cache lock prevent conflicting writers.

Memory scales with `(core + 2*halo)²`, core result arrays and worker count, not total output raster area. Task/event records stream to disk. Per-time summaries grow with the fixed daylight sample count. A source index grows with file count. Disk usage and processing time still grow with area and directions. Concurrent RSS sums count shared pages in each process, so are conservative relative to unique physical memory. The configured memory budget is a preflight estimate, supplemented by one-worker calibration with 25% headroom for parallel runs; it is not a hard memory limiter.

Lossless PNGs are full-grid only below a fixed four-million-pixel threshold; larger regions use individually georeferenced core pieces with JSON sidecars. GeoTIFFs are always fully assembled via bounded window writes and allow BigTIFF. Preview reads are bounded to a longest-side limit (≤4096), use nearest labels, and state display resolution. MP4 frames stream one at a time to the encoder. PNG roundtrips and decoded video frame count are checked before completion. Black is shaded, white is sunlit, gray is invalid; scientific encoding remains 1/0/255.

The old local web viewer and old photo-time simulation continue to refer to preserved historical outputs. The new required deliverables are the native-tile daylight rasters, PNGs, JPG, MP4, quality maps and run inventory. No registered photo validation or full-Hong-Kong production run was performed.

The final memory monitor samples the parent, bounded multiprocessing workers, and known ImageIO encoder/decoder processes. It obtains media PIDs from the installed, locked ImageIO versions rather than a system-wide process listing; metadata explicitly reports whether media tracking succeeded. The encoder uses one thread. See QA for separate parent and combined workflow peaks.
