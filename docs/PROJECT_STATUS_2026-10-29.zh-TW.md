## 3. 項目定位及與熱影像研究的關係

目前有兩個相關但獨立的程式庫，均位於：

`/Volumes/My Passport for Mac/Projects`

| 程式庫 | 主要任務 | 目前角色 |
|---|---|---|
| `HEAT_INDEX_ESTIMATION_UROP_2627FALL` | 無人機可見光／熱影像、地表分類、溫度與 ΔT 分析 | 已完成 Phase 2 的研究基礎 |
| `shade_watch_hk` | 使用 DSM 和太陽位置計算日照／陰影 | 正在獨立發展及驗證的遮蔭模擬項目 |

整體研究方向是：先產生可信且空間對齊的遮蔭資訊，再與地表分類及溫度資料結合，研究相同地表在不同遮蔭條件下的 ΔT。這個整合尚未完成，不能將現有陰影圖直接解讀為降溫效果或 ΔT 預測。

熱影像主項目的既有能力包括影像配對、審核對齊／ROI、地表分類、溫度提取與 QA、標準化像素資料、ΔT 分組統計，以及符合條件的跨時刻分析。其定義為：

`ΔT = 地表溫度 − 環境溫度`

部分既有環境值源自 TAT3 匯出參數，仍屬暫定值，不能自動等同獨立量測的氣象氣溫。真正 DJI 溫度提取依賴 Windows 環境；Mac 可使用已提取且附來源資訊的溫度矩陣進行下游分析。

主項目於 2026 年 9 月 24 日完成 Phase 2 並凍結在 `phase2-Completed`，有 Windows／Mac 回歸及跨機重現證據。其既有 shadow 欄位及分析接口不代表已完成可靠陰影判讀；歷史全零遮蔭遮罩也不能單憑數值被解讀為「全部已確認無陰影」。

## 4. Shade Watch 現在可以做什麼

### 4.1 科學問題與計算方式

程式回答的是：在指定區域和時間，依據現有 DSM 及既定模型，哪些地表像素被已知障礙物遮擋，哪些可判定為日照，哪些資料不足而不能可靠判斷？

基本資料流是：

`區域／時間請求 + DSM → 原生網格與支持資料 → 遮擋角快取 + 太陽位置 → Shade／Quality → 結果索引、統計及可選展示媒體`

這是受 Shade Watch 論文啟發的獨立實作，保留方向查找表的概念，使用已記錄的像素中心射線搜尋方法。不是已證明與原論文完全等價的重現，也尚未完成實地觀測驗證。

目前預設方向方法為最近 5°（`nearest5`），模型採用 1 km 搜尋／緩衝範圍。V1 也提供 `nearest2_5` 和 `direct` 選項；直接使用未分箱的方位角仍不代表物理或次像素精度已被驗證。1 km 搜尋條件不是任意修改 JSON 就能當作已驗收的新模型。

### 4.2 功能範圍

| 功能 | 已有能力及限制 |
|---|---|
| 區域選擇 | 指定單張／多張原生瓦片、以經緯度選取瓦片、自訂範圍或裁切 |
| 多瓦片 | 支持完整矩形的原生瓦片組合；缺瓦片、重複與孔洞等會被檢查 |
| 時間查詢 | 支持精確時刻、時刻列表、多日期，以及按間隔取樣的白天序列 |
| 只做規劃 | 檢查輸入與快取、列出所需方向和資源估算，不啟動遮擋角計算或生成結果 |
| 快取重用 | 在科學輸入相容時重用原生瓦片方向快取；新時間需要新方向時補算 |
| 批次管理 | 規劃、提交、執行、狀態查詢、取消、恢復；保留任務與失敗記錄 |
| 完整性與恢復 | 檢查已提交成果的內容與校驗資訊；按依賴關係修復所需的損壞或缺失成果 |
| 資源與估算 | 提供本地資源准入、耗時估算及抽樣資源監測；估算不是全港運行保證 |
| 結果組合 | 支持組合輸出；亦可透過邏輯拼接索引按指定時間與窗口讀取多份結果 |
| 媒體匯出 | 可選 JPG／MP4，兩者預設關閉；媒體任務與科學計算分開管理 |

一般更換 V1／V2 的區域與時間，應修改請求參數而不是演算法程式。程式會從指定本地 DSM 集合選取所需的周邊支持資料，不會自動下載缺失資料。

V2 預設一個 worker，上限四個；其協調與恢復保證針對本地儲存。跨機共享狀態庫、網路檔案系統和雲端同步不屬於這套本地協調保證。裁切較小輸出不代表首次計算一定很小，因為科學快取仍可能需要計算完整的所屬原生瓦片。

### 4.3 輸入

| 輸入 | 內容 |
|---|---|
| DSM | CEDD 2020 地表高程 GeoTIFF；收尾清單記錄 3,310 張，0.5 m、EPSG:2326 |
| 區域 | 原生瓦片名稱、經緯度選擇點，或 EPSG:2326 範圍；自訂模式可配合寬高 |
| 時間 | 指定時刻及時區，或日期與取樣間隔；示例通常使用 Asia/Hong_Kong |
| 執行設定 | 輸出位置、快取位置、worker、資源預算、是否生成媒體與統計等 |

既有原生瓦片通常為 750 × 600 m、1,500 × 1,200 像素。原生尺寸與座標以 GeoTIFF metadata 為準。全港下載及原科大集合現分別位於：

- `data/raw/dsm/2020/D12.DSM.TIFF/`：全港下載集合。
- `data/raw/dsm/2020_HKUST_Around/D12.DSM.TIFF/`：保留的 19 張歷史科大集合。

歷史驗收與估算校準必須保留其固定輸入，不能直接用新增的全港資料代替。新增支持資料可能合理地改變快取身份和品質分類。

### 4.4 輸出

| 輸出 | 用途與解讀 |
|---|---|
| Shade GeoTIFF | 正式像素分類：1＝陰影、0＝日照、255＝無效／不確定 |
| Quality GeoTIFF | 記錄有效性及無法判斷的原因，例如目標 DSM 缺失或迎光搜尋支持不足 |
| 逐幀狀態與結果索引 | 保存時間、來源、網格、太陽條件、路徑、統計與完整性資訊 |
| JPG／MP4 | 供展示的圖像與時間序列，不能替代原生解析度科學資料 |
| 批次狀態與收據 | 保存任務執行、重試、恢復及出版結果的來源關係 |
| 邏輯拼接索引 | 引用多份原始結果，無須強制生成一張龐大的實體拼接圖 |

展示圖的圖例為：黑色＝陰影、白色＝日照、灰色＝無效／不確定。灰色不能直接當作陰影。正式分析應讀取 Shade／Quality，而不應從有損 JPG 或影片顏色反推原始像素標籤。

### 5.3 仍待處理的 NoData 問題

先前討論的核心問題是：「全港 DSM 已下載，為什麼長洲仍有灰色區域，且灰白邊界會跳動？」

已確認的區分是：

1. 目標像素本身可能沒有 DSM 高程。對同一區域而言，這個缺失位置不會隨太陽改變。
2. 目標本身有高程，但朝太陽方向的 1 km 搜尋路徑可能穿過 NoData，令日照判斷缺乏完整支持。
3. 太陽方向改變時，搜尋距離仍是 1 km，但路徑經過的像素會變。最近 5° 的分箱也會令方向按離散步長切換。

因此「檔案齊全」不代表「所有像素有有效高程」。海面與陸地缺資料需要明確的科學處理政策；單純縮小角度間隔可能減輕跳動，但不會補回缺失資料。不能未經驗證就把灰色全部改成日照。

### 8.2 架構說明的適用範圍

`docs/ARCHITECTURE.md` 對 DSM、快取、分類、metadata 和早期六瓦片流程有詳細解釋，但不是完整的 V2 操作手冊。

| 項目 | 早期架構所述 | 新版 V1／V2 |
|---|---|---|
| 使用入口 | `src.shade_watch`、`pipeline.py` | V1 查詢及 V2 批次介面 |
| 結果索引 | `result_inventory.json` | `result_index.json` |
| 快取 | `horizon_cache_1km` | `shade_v1` 體系；V2 預設 `v2_default` |
| 太陽參考 | 早期合體以聯合區域中心為參考 | 每張原生瓦片保留固定參考點 |
| 狀態管理 | 舊任務／逐幀記錄 | 批次狀態庫、嘗試記錄與執行收據 |
| DSM 目錄 | 當時 2020 目錄只有 19 張科大資料 | 現在全港與原 19 張集合分開 |

因此新舊差異不只在文件名稱。舊快取不會自動被視為科學相容。現行 V2 也會保護舊的 V1／V2 schema-1.0 結果索引，拒絕直接就地改寫；新任務需使用新輸出目錄，可明確指定重用相容科學快取。歷史結果應保留原定義。

閱讀原理可參考架構說明；實際新任務應查閱 V1／V2 指南及科學政策。本文只記錄這項文件欠帳，沒有改寫原文件。

### 8.3 舊網頁目前做什麼

`web/index.html` 是已完成結果的播放器，提供時間滑桿、逐幀播放、太陽角度、有效像素比例及滑鼠座標／分類查詢。它沒有提交 V2 任務、選區後啟動計算或查看批次狀態的控制功能。

程式固定讀取：

`../outputs/600x450/result_inventory.json`

因此重新執行 V2 不會自動更新網頁；只要舊結果仍在，它仍會展示早期科大 600 × 450 m 的結果。

### 8.4 為什麼只換路徑仍然不行

已對照早期科大結果與長洲 V2 索引，兩者資料欄位不同：

| 網頁需要的資訊 | 舊結果 | 長洲 V2 結果 |
|---|---|---|
| 寬高 | `study.output_pixels` | `grid.width`、`grid.height` |
| 地理定位 | `study.output_bounds_m` | `resolved_bounds`、`grid.transform` |
| 每幀影像 | `frame.png` | `frame.raster` 指向 GeoTIFF；展示圖另列於 `media` |
| 太陽角度 | 每幀單一角度欄位 | `solar_by_tile` 按瓦片記錄 |

如果只把讀取路徑改成 V2 索引，舊網頁會找不到 `study` 等欄位；即使修復尺寸讀取，還有圖像、角度及路徑解讀等問題。新版索引中的本機檔案路徑也需要轉換為適合網頁存取的資源路徑。

舊 PNG 保存分類值 0／1／255，網頁讀值後再塗成白／黑／灰。JPG 則是供人看的媒體，可能包含縮放、文字圖例及有損壓縮。因此不能把 JPG 直接交給舊的分類解碼程序，否則像素查詢與座標對應沒有可靠依據。

將來若要更新網頁，可再決定只做 JPG／MP4 瀏覽，或保留精確科學像素與品質原因查詢。後者需要科學資料讀取或保留標籤與座標的展示資料轉換。有效 V2 模擬結果通常可以重用，不必為了更新網頁而重算全部遮擋角。這些只是供後續決策的選項，本次沒有選定或實作。
