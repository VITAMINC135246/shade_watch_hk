# 分别运行原生 tile

单独运行时，每个 tile 使用自己的原生边界、几何中心和该输出范围对应的不确定性阈值。日期读取 `config/study_area.md`；当前是 2026-01-07，香港时间，白天每 10 分钟一帧。每块仍按 0.5 m 像素计算，搜索 1 km，每侧读取 1 km 的 DSM buffer。

单 tile 的太阳参考点及阈值与六 tile 合体版共享的参考点及阈值可能不同，因此独立运行的结果不要求与合体图裁片逐像素一致。输入缺失的处理规则相同。

## 手动运行一块

先进入项目目录，再执行：

```sh
cd '/Volumes/My Passport for Mac/Projects/shade_watch_hk'

.venv/bin/python -m src.shade_watch \
  --tile '12NW6A(e845n822,e845n822).tif' \
  --workers 1 \
  --output outputs/manual_12NW6A_20260107
```

`--tile` 使用 DSM 的准确文件名，自动选择 native_tile 模式。输出目录要明确命名；改变日期或输入参数后，使用新的目录。省略 `--tile` 时，默认由 `config/study_area.md` 中保存的位置选择原生 tile。

## 顺序运行这六块

```sh
.venv/bin/python -m src.batch_tiles \
  --config config/mosaic_6tiles.json \
  --output outputs/individual_6tiles_20261001
```

这条命令只从配置读取六个文件名和科学设置，按顺序为每个 tile 启动一个新的单进程运行。合体配置中的 3 workers 在此明确改为每个独立 tile 使用 1 worker；六块之间不并行。每块有独立输出目录：

| tile | 输出子目录 |
| --- | --- |
| 11NE10B | 11NE10B/ |
| 12NW6A | 12NW6A/ |
| 11NE10D | 11NE10D/ |
| 12NW6C | 12NW6C/ |
| 11NE15B | 11NE15B/ |
| 12NW11A | 12NW11A/ |

每个目录包含代表 JPG、全天 MP4、完整 GeoTIFF、质量栅格和无损 PNG。`latest_batch.json` 汇总最近一次批量运行；`batch_runs/<运行编号>/` 保留每次运行的配置、日志和计时，不会因下次运行覆盖首次计时。

相同命令可续跑：程序会校验并复用有效 horizon 缓存和科学栅格，重新导出图片/视频。完成过的 tile 在续跑时也会进入校验和导出流程；日志中的 computed/reused 数量区分新计算与缓存复用。

## 如何理解耗时

`wall_seconds` 是每块独立进程从启动到退出的实测用时。各块 `result_inventory.json` 的 `performance` 还提供：

- `preprocessing_seconds`：文件校验、网格设置、统计、太阳时序等准备工作。
- `horizon_seconds`：计算或校验复用全部所需方向的 horizon 缓存。
- `export_seconds`：生成/校验科学栅格、PNG、JPG 和视频，并解码检查视频。

固定 tile 尺寸、日期采样、方向数量、输入清单和单进程串行设置时，总时间通常近似于每块耗时的累加，可用 N × 实测平均耗时做初步估算。各 tile 的有效 DSM 像素比例、地形、磁盘读写和系统负载会造成差别；NoData 多的 tile 通常较快。

缓存复用会大幅改变耗时：改日期时，网格和 DSM 未变且已有对应方向缓存，可以复用这些方向；新日期需要的额外方向仍需计算。固定尺寸/并发时，生产计算的大数组内存不会随 tile 数线性增加；总磁盘占用和首次总计算量通常随 tile 数增加。

当前每个独立进程仍会扫描/校验原始文件清单并做源图幅接缝审计。若未来源文件数也大幅增加，这部分开销会增加，不能据此次六块试跑承诺全港严格线性增长。多进程也不会保证按进程数等比例加速，需要实测 CPU、内存和磁盘竞争。

## 本次六块实测

模拟日期：2026-01-07（香港时间），白天每 10 分钟一帧，共 65 帧/块。每块 750 × 600 m，1500 × 1200 科学像素，0.5 m 分辨率，1 km 搜索及 buffer。每块采用自身几何中心，单计算块、单 worker，串行运行。

全部是无 horizon 缓存复用的首次完整计算，每块新计算 27 个方向。完整用时包含准备、阴影计算、栅格与图片导出、视频编码及解码验证；“方向计算”列仅为 horizon 阶段。

| Tile | 完整用时 | 方向计算 | 输出与验证 | 目标 DSM 覆盖率 |
| --- | ---: | ---: | ---: | ---: |
| 11NE10B | 5 分 17 秒 | 261.2 秒 | 52.2 秒 | 100.0% |
| 12NW6A | 3 分 09 秒 | 157.3 秒 | 26.0 秒 | 61.7% |
| 11NE10D | 5 分 08 秒 | 257.4 秒 | 45.2 秒 | 100.0% |
| 12NW6C | 4 分 41 秒 | 244.4 秒 | 31.5 秒 | 96.3% |
| 11NE15B | 5 分 15 秒 | 253.4 秒 | 55.7 秒 | 100.0% |
| 12NW11A | 5 分 01 秒 | 252.6 秒 | 44.2 秒 | 100.0% |

六块成功运行耗时合计 **28.52 分钟（1711.24 秒）**，平均 **4.75 分钟/块（285.21 秒）**。

计时说明：原批次第六块在导出阶段中断，前五块已经完整保存。第六块使用独立空缓存从头运行，取得可比较的首次运行计时。以上合计为六次成功完整运行的进程耗时之和，不包括中断尝试及期间空闲时间，不是从最早启动到最后结束的自然时长。原日志和中断输出保留在 batch_runs/，详细秒数见 latest_batch.json。

核对结果：六块均为单原生计算块，边界与源 GeoTIFF 一致，参考点为各自几何中心；每块 65 个科学栅格、65 个质量栅格、65 张无损 PNG；每个视频均解码确认 65 帧。运行记录中的原始 DSM 文件哈希与合体版一致。

在同一台电脑、相同输入规模和设置下，串行首次运行可用 N × 此次平均用时估算。DSM 有效像素比例、方向数量、缓存、系统负载和磁盘读写会影响速度；扩大原始文件清单还会增加文件校验与接缝审计成本，因此不是严格线性保证。
