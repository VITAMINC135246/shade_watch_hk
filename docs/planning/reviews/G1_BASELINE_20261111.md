No content hashes for the data trees.

## Comparison procedure for the pre-check

1. Re-run the listing script on the same trees.
2. Every baseline unit must be present with the same digest. A changed digest in an existing unit is a write-scope finding.
3. Every new unit must lie in a location that `SW-G1.0` allows ("Write scope and allowed files"): `data/processed/dsm_catalogues/`; a new view folder, `current-nl_rotterdam_dsm05.json` and `build-nl_rotterdam_dsm05.lock` in `dsm_views/sea_fill_v2_2/`; new namespaces `shade_v1/sea_fill_v2_2_<Rotterdam id12>`, `shade_v1/sea2_2_fill_impact_<id12>`, `shade_v1/g1_*`; `outputs/shade_map_g1_dev_*`; new entries for new run names in `outputs/shade_map_work/`, its `.locks/`, `outputs/region_views/`, `outputs/sea2_2_diagnostic_work/` and its `.locks/`.
4. Planner files: identical SHA-256.
5. G1-03 in particular: `P/shade_v1/sea_fill_v2_2_8ee51b017411` must keep its digest.

Known noise: `.DS_Store` files change when Finder opens a folder. Any such change must be attributed, not silently excused.
